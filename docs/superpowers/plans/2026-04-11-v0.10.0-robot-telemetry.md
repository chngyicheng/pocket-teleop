# v0.10.0 Robot Telemetry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show live robot position (x, y) and heading on the UI. Requires a new ROS2 subscription on the server, a new WebSocket message type, and a new display panel on the client.

**Architecture:**
```
ROS2 /odom (nav_msgs/msg/Odometry)
    │ subscribed by TeleopNode
    ▼
TeleopServer::broadcast(json)
    │ WebSocket server → connected client
    ▼
TeleopClient.handleMessage → onOdom callback
    │
    ▼
index.html: x/y display + heading indicator
```

**Odom is optional** — robot may not publish `/odom`. Panel only shows when messages arrive. Topic name configurable via ROS2 parameter (default `/odom`).

**Yaw from quaternion:**
```
yaw = atan2(2*(qw*qz + qx*qy), 1 - 2*(qy*qy + qz*qz))
```

**Rate limiting:** `/odom` can publish at 50+ Hz. Server throttles to 10 Hz (every 100ms) before sending over WebSocket to avoid saturating the connection.

- [ ] **Step 2: Implement in `teleop_server.cpp`**

Add after `on_message`:

```cpp
void TeleopServer::broadcast(const std::string& message) {
  std::lock_guard<std::mutex> lock(client_mutex_);
  if (!has_client_) return;
  websocketpp::lib::error_code ec;
  ws_server_.send(active_client_, message, websocketpp::frame::opcode::text, ec);
  // Ignore ec — if client disconnected, has_client_ will be cleared by on_close.
}
```

- [ ] **Step 4: Subscribe in `teleop_node.cpp`**

  const auto odom_topic = get_parameter("odom_topic").as_string();

  odom_sub_ = create_subscription<nav_msgs::msg::Odometry>(
    odom_topic, 10,
    [this](const nav_msgs::msg::Odometry::SharedPtr msg) {

Add `publish_odom` method declaration to `teleop_node.hpp`:

```cpp

```

Add implementation to `teleop_node.cpp`:

```cpp
void TeleopNode::publish_odom(const nav_msgs::msg::Odometry::SharedPtr& msg) {
  const auto now = std::chrono::steady_clock::now();
  if (now - last_odom_sent_ < ODOM_INTERVAL) return;
  last_odom_sent_ = now;

  const auto& pos = msg->pose.pose.position;
  const auto& q   = msg->pose.pose.orientation;
  // Quaternion → yaw (rotation around Z axis)
  const double yaw = std::atan2(
    2.0 * (q.w * q.z + q.x * q.y),
    1.0 - 2.0 * (q.y * q.y + q.z * q.z));

  nlohmann::json odom = {
    {"type",    "odom"},
    {"x",       pos.x},
    {"y",       pos.y},
    {"heading", yaw},   // radians; client converts to degrees
  };
  server_->broadcast(odom.dump());
}
```

Add `#include <nlohmann/json.hpp>` to `teleop_node.cpp` if not already present.

## Task 6 — AGENTS.md update

**Files:** `AGENTS.md`

- [ ] Update Handoff State: note v0.10.0 complete; test counts
- [ ] Update Head SHA
- [ ] Add deviations:

| Deviation | Location | Why accepted |
|---|---|---|
| Odom throttled to 10 Hz server-side | `server/src/teleop_node.cpp` | `/odom` often published at 50+ Hz; sending every message over WebSocket would saturate a Raspberry Pi's uplink; 10 Hz is sufficient for display |
| Heading sent as radians; UI converts to degrees | Protocol, `index.html` | Radians are the native ROS2 unit; conversion in UI keeps the protocol clean and avoids floating-point precision loss from server-side degree conversion |
| Odom panel hidden until first message | `web-client/index.html` | Robots that don't publish `/odom` should not show a stale or empty panel; hidden-by-default prevents confusion |
| `broadcast()` ignores `error_code` from `ws_server_.send` | `server/src/teleop_server.cpp` | Client disconnect sets `has_client_ = false` via `on_close`; silent error on a stale send is harmless and avoids a race condition check |
