## 審查維度

每文件逐一檢查以下維度，記錄發現：

1. **Critical bugs** — 導致崩潰或嚴重錯誤行為
2. **Logic issues** — 微妙錯誤、錯誤假設
3. **Missing test coverage** — 有代碼路徑但無對應測試
4. **Code smell / naming** — 不阻塞但值得記錄

## 文件一：`web-client/src/video_source.ts`

### 具體檢查點

- **`VideoSourceType` vs `VideoSourceMode`**：兩者區別是否有意義？`VideoSourceType` 是否在任何地方被實際使用（非僅導出）？
- **`validate()`**：
  - 所有分支是否正確？
  - `url.trim()` 結果存於 `t`，但 apply 傳入的是原始 `url`——validate 後 apply 用 `url`（非 `t`）傳給 save 和 buildMtxSource，是否有前後空格問題？
- **`buildMtxSource()`**：MJPEG 模式被排除在外——確認這是正確設計（MJPEG 不走 MediaMTX）
- **`save()`**：
  - rtsp/udp/srt 共用 `video-rtsp-url` key——切換 udp→srt 時，舊 URL 是否正確覆蓋？
  - 從 mjpeg 切換至 udp：`video-mjpeg-url` 是否被移除？從 udp 切換至 mjpeg：`video-rtsp-url` 是否被移除？
- **`loadSaved()` 返回值**：`rtspUrl` 字段名對 udp/srt 模式是否造成語義混淆？是否影響調用方？
- **`apply()` 時序**：
  - MJPEG：`save()` 先於 `onMjpegUrl()` 調用——若調用方在 `onMjpegUrl` 回調中讀取 localStorage，是否能讀到正確值？
  - 非 MJPEG：`onMjpegUrl(null)` 在 fetch **之前**調用——若 fetch 失敗，MJPEG 圖像已被清除但 MediaMTX 未切換，UI 狀態是否一致？
  - `disabled` 模式：`onMjpegUrl(null)` 是否被調用？（應調用，確認）

## 文件二：`web-client/test/video_source.test.ts`

### 具體檢查點

- **未測代碼路徑**：
  - `apply('mjpeg', url)` 在無 `onMjpegUrl` 回調時——是否返回 `'ok'`（不崩潰）？
  - `apply('disabled')` 是否調用 `onMjpegUrl(null)`？
  - `apply('udp')` 成功後，`video-mjpeg-url` 是否被移除（即 save 的跨 key 清理）？
  - 從 mjpeg 切換至 ros2：localStorage 的 `video-mjpeg-url` 是否被移除？
- **`beforeEach` localStorage.clear()**：所有 describe 塊是否受此保護？（`beforeEach` 在頂層，確認 scope）
- **斷言精度**：`toMatch(/required/i)` 等 regex 是否足夠精確，還是應用精確字符串？
- **`VideoSourceType` import**：測試文件 import 了此類型但從無使用——是否應移除？

## 文件三：`web-client/index.html`

### 具體檢查點

- **XSS 風險**：`mjpegImg.src = url`，url 來自用戶輸入或 localStorage——`<img src>` 賦值本身不執行 JS，但確認是否有其他注入路徑
- **WhepClient 競態**：WhepClient 在串流到達時調用 `showVideoStream(stream)`，強制 `videoEl.style.display = 'block'`——若 MJPEG 正在顯示時 WhepClient 重連，`videoEl` 會覆蓋 MJPEG 顯示。這是 bug 還是可接受行為？
- **Restore IIFE**：
  - mjpeg 模式直接調用 `setMjpegDisplay(mjpegUrl)` 而非 `picker.apply('mjpeg', mjpegUrl)`——繞過了 save() 調用（但 localStorage 已有值，無需再 save），以及 validate()（URL 已驗證過才能存入，合理）。是否有遺漏的副作用？
  - `videoSourceSelect.value = mode` 賦值：若 mode 為 localStorage 中的舊值（如某個已廢棄模式），select 會靜默退回空值——是否需要驗證？
- **`<option>` 完整性**：`VideoSourceMode` 的所有值（`ros2`/`rtsp`/`udp`/`srt`/`mjpeg`/`disabled`）是否在 `<select>` 中均有對應 `<option>`？
- **`updateUrlField()` 調用**：頁面加載時 restore IIFE 調用了 `updateUrlField()`——是否在 `videoSourceSelect.value` 賦值**之後**調用？（需確認順序）
- **Apply 後 URL trim**：`const url = videoUrlInput.value.trim()` 傳給 `picker.apply(mode, url)`，但 `validate()` 內部再次 trim——雙重 trim 是否有問題？（無問題，但確認）
