# v0.5.0 Design Spec — Keyboard Controls, Connection Polish, Touch Indicator

**Date:** 2026-03-30
**Milestone:** v0.5.0

---

## Overview

Four coordinated improvements to the web client:

1. **Axis remapping** — left joystick takes forward/back + rotate; right joystick takes strafe. Enables one-handed driving.
2. **KeyboardHandler** — new `src/keyboard_handler.ts` module; WASD + arrow keys as a third input source.
3. **Connection status polish** — fixed-interval infinite retry; "last seen Xs ago" appended to connected pill when link is silently degrading.
4. **Input UX** — touch joystick dot-ring indicator on touch devices; persistent floating input-mode bar at bottom of screen.

No server changes. No new dependencies.

---

## 1. Axis Remapping

### Current mapping

| Joystick | Axis | Value |
|----------|------|-------|
| Left vertical | lx | −y |
| Left horizontal | ly | +x |
| Right horizontal | az | −x |

### New mapping

| Joystick | Axis | Value |
|----------|------|-------|
| Left vertical | lx | −y |
| Left horizontal | az | −x |
| Right horizontal | ly | +x |
| Right vertical | — | unused |

### Rationale

Left stick alone covers forward/back + rotate — the two axes needed for differential-drive robots. Right stick adds strafe for holonomic robots. One-handed operation is possible with just the left zone.

### Change location

`index.html` touch joystick setup block only. Two lines:

```js
// Left joystick
onMove: (x, y) => { joyLx = -y; joyAz = -x; client.sendTwist(joyLx, joyLy, joyAz); }
onEnd:  ()     => { joyLx = 0;  joyAz = 0;  client.sendTwist(0, joyLy, 0); }

// Right joystick
onMove: (x, _) => { joyLy = x;  client.sendTwist(joyLx, joyLy, joyAz); }
onEnd:  ()     => { joyLy = 0;  client.sendTwist(joyLx, 0, joyAz); }
```

## 2. KeyboardHandler (`src/keyboard_handler.ts`)

### Interface

```ts
export interface KeyboardHandlerOptions {
  velocity?: number;          // constant axis value when key held (default 0.5)
  onTwist: (lx: number, ly: number, az: number) => void;
  onActivity?: () => void;    // fires on keydown regardless of enabled state
}

export class KeyboardHandler {
  constructor(options: KeyboardHandlerOptions)
  start(): void               // attach keydown/keyup listeners, start poll interval
  stop(): void                // detach listeners, clear interval
  setEnabled(enabled: boolean): void
}
```

### Key map

| Key | Axis | Direction |
|-----|------|-----------|
| W | lx | +velocity |
| S | lx | −velocity |
| A | az | +velocity (turn left = CCW = positive az) |
| D | az | −velocity (turn right = CW = negative az) |
| ArrowLeft | ly | −velocity |
| ArrowRight | ly | +velocity |
| ArrowUp | — | unused |
| ArrowDown | — | unused |

### Behaviour

- Tracks held keys in a `Set<string>` via `keydown`/`keyup` DOM events.
- Poll interval: 200ms (same as `GamepadHandler`). On each tick, reads the set and emits `onTwist` if enabled.
- Multiple keys can be held simultaneously (e.g. W + D = forward + turn right).
- `onActivity` fires on any `keydown` regardless of `enabled` — allows input-source switching while touch/gamepad is active.
- `start()`/`stop()` attach and remove the DOM event listeners. Only attach when started to avoid leaking listeners.
- Guard: `typeof document === 'undefined'` check for test environments that lack a DOM.

### Integration in `TeleopClient`

`TeleopClient` does **not** own `KeyboardHandler` — it is wired up in `index.html` alongside the existing touch joystick and gamepad setup, consistent with how `TouchJoystick` is wired. `TeleopClient.sendTwist` is called directly from `KeyboardHandler.onTwist`.

### Testing

Unit tests in `test/keyboard_handler.test.ts`:
- Keys held → correct lx/ly/az values emitted
- Multiple keys held simultaneously
- `setEnabled(false)` suppresses `onTwist` but not `onActivity`
- `stop()` detaches listeners (no events fire after stop)
- Keys released → values return to zero

## 3. Connection Status Polish

### 3a. Infinite retry with fixed interval

**Current behaviour:** exponential backoff, max 5 retries, then `onClose` fires and stops.

**New behaviour:**
- Fixed 5 000 ms interval between attempts. No exponential increase.
- Retry forever — no `maxRetries` cap. `onClose` fires only on intentional disconnect.
- `onReconnecting(attempt, delayMs)` signature simplified — `maxAttempts` parameter removed (always `∞`).
- Status pill during retry: `⟳ Reconnecting… (attempt N)` with no countdown (fixed interval makes countdown less useful; remove to simplify).

**`TeleopClientOptions` changes:**
- Remove `maxRetries` option (no longer meaningful).
- `retryBaseDelayMs` renamed `retryIntervalMs` (default 5000).
- `onReconnecting` signature: `(attempt: number) => void`.

### 3b. "Last seen" in connected pill

**Tracking:** `index.html` tracks `lastReceivedAt = Date.now()` updated on both:
- `onStatus` callback
- `onPong` callback (new — see below)

**Display rule:** a `setInterval` at 1 000 ms updates pill text when `inputSource` is connected:
- If `Date.now() - lastReceivedAt < 2000` → `● Connected — RobotType`
- If ≥ 2 000 ms → `● Connected — RobotType · Xs ago` (integer seconds, no decimals)

**`TeleopClient` change:** add `onPong?: () => void` to `TeleopClientOptions`. Wire in `handleMessage` when `msg.type === 'pong'`. No other changes to `TeleopClient`.

### 3c. Velocity bar responsiveness

`.vel-fill` CSS transition reduced from `100ms` to `0ms` (removed). Direct DOM update is fast enough; the transition was adding perceptible lag during active driving.

## 4. Input UX

### 4a. Touch joystick dot-ring indicator

**Rendered by:** `TouchJoystick` constructor, conditional on `navigator.maxTouchPoints > 0`. Not rendered on desktop browsers.

**DOM structure** (appended to container, alongside `.joystick-base`):

```html
<div class="joystick-hint">
  <div class="joystick-hint-dot"></div>
</div>
```

**Styling:**
- `.joystick-hint`: 80px × 80px circle, centered in zone (`position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)`), semi-transparent white border (`2px solid rgba(255,255,255,0.25)`), `pointer-events: none`.
- `.joystick-hint-dot`: 16px × 16px filled circle, centred, `background: rgba(255,255,255,0.3)`.

**Visibility logic (inside `TouchJoystick`):**
- Shown by default (element exists in DOM).
- Hidden (`display: none`) immediately in `onPointerDown`.
- Restored (`display: ''`) immediately in `onPointerUp` / `onPointerCancel`.

### 4b. Input mode floating bar

**DOM:**

```html
<div id="input-mode-bar"></div>
```

Placed in `<body>` outside `#video-panel`, after the touch joystick zones.

**CSS:**
- `position: fixed; bottom: 16px; left: 50%; transform: translateX(-50%)`
- Semi-transparent dark pill: `background: rgba(0,0,0,0.55); backdrop-filter: blur(4px)`
- `padding: 6px 16px; border-radius: 20px`
- `font-size: 11px; color: rgba(255,255,255,0.85); white-space: nowrap`
- `z-index: 20` — above video panel, below settings drawer backdrop (`z-index: 30`)
- `pointer-events: none`

**Content per input source:**

| Source | Bar text |
|--------|----------|
| `touch` | `◉ Touch` |
| `gamepad` | `⊞ Gamepad` |
| `keyboard` | `⌨ W/S fwd · A/D turn · ←/→ strafe` |

**Update:** `setInputSource(source)` helper in `index.html` updates both `inputSource` variable and `input-mode-bar` text in one place. All existing source-switching code calls `setInputSource` instead of setting `inputSource` directly.

## 5. Input Source Switching — Updated Rules

`inputSource` values: `'touch' | 'gamepad' | 'keyboard'`

| Event | Action |
|-------|--------|
| `gamepadconnected` | → `'gamepad'` |
| `gamepaddisconnected` | → `'touch'` |
| `GamepadHandler.onActivity` | → `'gamepad'` |
| `KeyboardHandler.onActivity` | → `'keyboard'` |
| `pointerdown` (touch type) on zone | → `'touch'` |

First-input-wins: each `onActivity` fires only on real input (axis > 0.1 or keydown), so whichever fires first takes control.

When switching **to** `'gamepad'`: hide joystick zones, enable gamepad.
When switching **to** `'keyboard'`: hide joystick zones, disable gamepad.
When switching **to** `'touch'`: show joystick zones, disable gamepad.
